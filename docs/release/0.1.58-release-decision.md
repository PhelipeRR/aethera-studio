# NeuralBridge 0.1.58 — release decision

Date: 2026-11-06

## Decision

Release 0.1.58 is a local validation release candidate, not an enterprise-ready
release. The honest product posture is:

| Area | Classification | Basis |
|---|---|---|
| TaskEngine | Core stable | Persisted lifecycle, approval, cancellation, recovery, evidence and retry contracts are covered by unit, integration and packaged E2E evidence. |
| Chat | Core stable | Packaged primary journey and Chat state E2E are green; real providers remain a separate gate. |
| Projetos / workspaces | Core stable | Fixture and project safety paths are covered; real user projects were not modified. |
| Memória / RAG | Core stable | SQLite persistence, scoped memory, redaction boundaries and local RAG tests are green. |
| Git Intelligence | Core stable | Read-only and authorized-operation boundaries are tested; destructive Git actions remain prohibited. |
| Workflows | Power tool stable | Versioned DAG/TaskEngine integration and persistence are locally validated. |
| Analytics | Power tool stable | Local provider-reported token analytics are available; no anonymous telemetry is enabled. |
| MCP | Core stable | Typed server/preload seams and redaction/security tests are green. |
| Extensions platform | Extension experimental | Manifest, checksum/Core compatibility, local lifecycle and rollback are validated; signed remote distribution is absent. |
| Neura | Extension experimental | Existing routes and local capabilities remain compatible, but real VoiceStudio/Spotify/device homologation is incomplete. |
| Velix | Extension experimental | Local video/motion pipelines are validated; real provider/channel operations remain gated. |
| Azure/TFS | Integration experimental | Local fake-server read/write approval is green; corporate endpoint and real credential homologation are not done. |
| Windows distribution | Blocked external | Unsigned installer works in an isolated smoke test; Authenticode, auto-update and a valid previous installer are unavailable. |
| Security | Core stable with external gates | Local redaction, IPC, path, credential-store and untrusted-content tests pass; real-provider logs and signed distribution remain unverified. |
| Real-environment homologation | Blocked external | Real credentials, corporate APIs, multiple Windows profiles and external services were intentionally not used. |
| Generated test artifacts | Retired candidate, pending inventory | Temporary/generated outputs are candidates for later cleanup only; none is deleted by this decision. |

## Validated scope

- Packaged Electron primary journey: 13/13.
- Packaged Chat state coverage: 7/7.
- Directed orchestrator/shared diagnostics and evidence tests: 60/60.
- TFS and extension simulated matrix: 5/5, repeated three times (15/15).
- Windows installer smoke test in `.release-test-install-2`: install exit 0,
  executable launch with isolated `NB_DATA_DIR`, uninstall exit 0, and data
  directory preserved.
- Typecheck, lint, Electron build, `npm run verify:dist` and `git diff --check`.

## Limitations and external blockers

- Claude and Codex binaries were detected, but authentication and real tasks
  were not queried or invoked automatically.
- No corporate TFS/Azure DevOps endpoint or PAT was used.
- YouTube, Spotify, VoiceStudio and real FFmpeg availability were not
  homologated in this release decision.
- The installer is unsigned; `signtool.exe` is unavailable.
- Automatic update, signed HTTPS extension registry and upgrade over a valid
  previous installer are not configured or proven.
- Real `%APPDATA%` preservation and multiple supported Windows profiles remain
  unverified.

## Conditions for an enterprise release declaration

Do not use “enterprise ready” until all of the following have observable
evidence in a disposable environment: signed Authenticode artifact, clean
install and upgrade over a valid prior version, automatic update with rollback,
real authenticated Claude/Codex read-only and edit tasks, real permission and
approval checks, corporate TFS read/write approval, signed HTTPS extension
registry, multi-profile Windows validation, and reviewed diagnostics/logs with
no secrets.

## Post-consolidation roadmap

1. Obtain signing infrastructure and make Authenticode verification a release gate.
2. Implement and test auto-update, rollback and failure recovery.
3. Establish a signed HTTPS extension registry with publisher trust, rotation and revocation.
4. Run real-provider homologation with explicitly supplied credentials and isolated projects.
5. Validate upgrade over a valid previous installer and multiple Windows profiles.
6. Harden extension sandboxing, permissions, provenance and package review.
7. Consider local, opt-in usage metrics only after explicit product/privacy approval.
8. Pay down maintenance debt: generated artifacts, stale plans/tests, duplicated integration fixtures and measured performance budgets.

## Next acceptance criteria

The next release gate closes only when the external blockers above have
evidence attached to the matrix. Until then, 0.1.58 is suitable for local
validation and controlled development, not enterprise distribution.
